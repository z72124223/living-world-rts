# 遊戲憲法 v0.3

> 狀態：正式設計基線。除非經主設計流程明確決議，後續設計與實作不得默默違反本文件。

## 1. 核心定位

- 遊戲是即時戰略（RTS）＋角色扮演（RPG）的持續活世界。
- 官方設計端必須能在世界運行期間插入劇本與世界事件。
- 世界的核心不是傳統等級成長，而是人物、裝備、組織、資訊、傷勢、歷史與玩家決策共同形成結果。
- 核心體驗以探索、擬真、不確定性，以及現實中難以取得的震撼、感動、恐懼、失去與敬畏為主。

## 2. 人物、身分與死亡

> 2026-09-06 使用者更正：肢體受傷造成能力影響與遊戲架構衝突，這部分暫停採用、待重新討論。下列既有傷勢描述保留供核對，不能據此先實作肢體減益；本輪只製作分件美術樣品。此更正不代表已改採傳統 HP，亦未定義替代傷害規則。

- 玩家、武將、NPC、普通士兵原則上共用同一套「人物」模型。
- 人物不是傳統 HP 容器；不採用「HP 歸零即死亡」作為底層生命規則。
- 傷害由命中部位、武器／傷害型態、穿透、防具與傷勢等規則推導。
- 傷勢可造成出血、骨折、失能、昏迷與死亡。
- **人物的一次生命永久死亡。**
- 普通人物可因重大行為被世界記住，成為知名人物、英雄或傳說。
- 具名武將是世界中的唯一「身分」，不是卡片或帳號資產；同一時間同一伺服器最多只能有一名活著且已揭露的同名武將。
- 具名武將死亡後，死亡的 `Character` 不復活；其具名身分解除占用並可重新回到角色池，由未來另一個新 `Character` 再次承載。
- 新承載者可保留該具名身分對前主人與重大前世事件的記憶，但當前所屬、主人與人生關係重新形成；記憶不等於所有權。

## 3. 能力與成長

- 武力、智力不是傳統 Level／經驗條的替代名稱，而是人物能力尺度。
- 武力可影響肉體能力、負重駕馭、武器控制及相關近戰表現；精確公式尚未鎖定。
- 智力可影響判斷、識破、戰術、指揮及資訊運用；精確公式尚未鎖定。
- 可研究《三國志大戰》的非線性武力與雙方智力差設計作為參考，但不得在未驗證前視為本遊戲公式。
- 後天能力（如武器熟練、騎術、指揮、工藝）與天賦尺度分離。
- 體力、疲勞、傷勢、負重屬於當前狀態，不等同於等級或生命值。
- 武將不得被壓縮成單一客觀稀有度／戰力排序；人物應具有不可完全互換的能力、人格、限制與情境價值。同一武將可能不適合某玩家，卻在另一種玩法、軍隊或局勢中極具價值。

## 4. 裝備與負荷

- 裝備原則上不以等級硬性禁止穿戴，而以實際使用代價形成限制。
- 裝備重量會影響體力消耗、移動、靈活性，以及閃避、格擋、反擊等戰鬥表現。
- 重裝不是輕裝的單純上位替代；不同負荷形成不同戰術用途。
- 人與坐騎都可具有自己的負荷與承載限制。

## 5. 組織與部隊

- 人物可獨立作戰，也可編入部隊。
- 部隊是人物的組織與聚合計算層，不是另一種人物。
- 任何部隊可包含「人物＋下級部隊」，形成統一組織樹：人物 → 小隊 → 上級部隊 → 軍團等。
- 部隊必須能動態拆分與合流；拆分／合流是組織關係變化，不複製人物。
- 編隊後可在小隊／部隊層聚合高頻計算，但具體人物仍保留自己的身分、裝備、傷勢與歷史，並承受具體結果。

## 6. 模擬原則

- 世界規則統一，但模擬解析度可以依重要度、距離、是否交戰等條件調整。
- 不應為武將、玩家、普通士兵建立彼此無關的戰鬥世界規則。
- 不同解析度切換必須盡可能保持統計與結果一致，避免玩家靠接近／離開戰場改變本應發生的結果。

## 7. 現實軍制優先鐵律

- 遇到現實軍隊／軍制已有成熟解法的問題，先查考現實制度，再抽象成遊戲規則。
- 包含但不限於：編制、指揮鏈、代理指揮、命令傳遞、通訊、後勤、偵察、傷兵、潰退與部隊組織。
- 只有當現實制度不符合遊戲性、世界觀／時代或效能需求時才修改，且應記錄修改理由。
- 正式職位、指揮順位與當前實際指揮權必須可分離。

## 8. 軍事通訊與情報

- 命令不應天然瞬間同步。
- 命令具有來源、內容、發出時間、目的地、傳輸媒介、延遲，以及可能失敗／遺失的狀態。
- 古代可使用喊話、旗號、鼓號、烽火、徒步／騎馬傳令與書面軍令等媒介。
- 複雜命令可需要真實傳令人物／傳令小隊；傳令者可以被阻截或死亡。
- 資訊可能因傳輸延遲而過期。
- 玩家與 NPC 原則上遵守同一套資訊規則，不免費獲得全知上帝視角。

## 9. 玩家舞台與高光

- 核心理念：給所有玩家一個舞台；遊戲是玩家表現自己的項目之一。
- 高光不以連續擊殺作為唯一核心，而應辨識真正改變戰局／世界的貢獻。
- 高光應可高頻、隨戰局演進呈現，而非只在結算播放一次。
- 商人、偵察、指揮、工匠、傳令者、殿後者等，只要真正改變局勢，都可成為高光主角。
- 戰鬥不是高 APM 操作考試；操作服務於部署、判斷、選擇與下令，並必須讓玩家有餘裕欣賞戰鬥過程與決策結果。

## 10. 世界歷史與記憶

- 玩家與 NPC 都可能成為世界歷史的一部分。
- 事件應可依重要度由普通紀錄逐步升格為重要事件、戰役紀錄、世界歷史與傳說。
- 重大事蹟未來可成為正史、地名、雕像、傳說人物或歷史物品的來源。
- 官方提供初始世界背景與規則，之後由官方事件與玩家行為共同書寫世界編年史。
- 具名身分的每一段生命都必須保留獨立歷史，不得因身分重新入池而覆蓋前一位承載者的人生與死亡。

## 11. 經濟與物品

- 遊戲內物品可由玩家交易並形成稀缺性與使用價值。
- 官方不以回收或現金交易作為核心機制，遊戲本身不直接建立現實現金交易流程。
- 物品的價值應盡量來自世界規則、用途、稀缺性、來源與歷史，而不是單純官方指定戰力數字。

## 12. 社群共創

- 長期方向允許社群投稿新單位、角色、武器、建築、劇情、地圖與模組等內容。
- 正式進入世界前應經社群測試／評價、規則檢查、官方與世界觀審核及平衡驗證。

## 13. 世代與繼承（長期方向）

- 永久死亡後，人物可透過子女／後代形成世代延續。
- 可繼承部分財產、家族、聲望、關係與歷史，也可能承受債務、仇敵等負面遺產。
- 單身玩家仍必須有完整遊戲路徑；未來可研究收養、指定繼承人、師徒、宗族、遺囑等不同傳承方式。

## 14. 玩家體驗守則

1. **禁止工作感**：不以每日任務、重複刷取、維護性操作、繁瑣管理維持遊玩時長。
2. **禁止高強度學習門檻**：世界可以很深，但玩家應透過觀察與經歷逐步理解，而不是先讀大量說明或攻略才能玩。
3. **複雜度留在世界裡**：底層模擬可以極深；玩家操作必須自然。複雜的是世界，不是操作。
4. **不確定性優先於公式答案**：玩家可以判斷風險，但不應永遠知道精確、可完全最佳化的結果。
5. **情緒價值高於數值成長**：震撼、恐懼、感動、探索、失去、發現與敬畏優先於單純數值提升。
6. **創造現實難以取得的體驗**：大規模戰場、真實指揮權、永久死亡、歷史形成、世界級事件等服務於此目標。
7. **戰鬥必須值得觀看**：模擬、AI、動畫、聲音、鏡頭與資訊呈現應共同使觀看戰鬥本身成為樂趣。

所有新系統都必須回答：**新增的複雜度由世界承擔，還是由玩家承擔？** 若主要變成重複勞動、查表、背公式或高頻微操，應重新設計。

## 15. 身分未定態與問名升格

- 未揭露人物可以處於「身分未定態」：後台存在多個潛在具名身分及可能性，但玩家不得看到精確機率。
- 日常行為、戰鬥、關係、世界經歷與玩家交談可影響身分收斂；玩家只能影響，不能指定或保證得到某位武將。
- 禁止把系統做成固定對話答案、好感度進度條、攻略查表或課金保證角色。
- 「問名」是第一版身分坍縮／升格方式，但長期可由自然世界事件觸發；核心是「世界終於需要知道這個人是誰」。
- 揭露前玩家可以猜錯、錯過人物；未揭露人物也可以死亡。世界不因玩家沒有注意就停止存在。
- 身分揭露後，在該生命存續期間固定，不得因玩家偏好改寫成另一位武將。
- 具名人物與玩家是關係而非帳號所有權；武將可以因忠誠、招攬、俘虜、背叛、政治與人際關係改變所屬。

## 16. 開發鐵律

- 不等待整款遊戲規劃完才實作。
- 採可演化核心＋垂直切片；每個里程碑必須維持可執行／可驗證狀態。
- 新點子先進研究／待辦，不得自動膨脹當前里程碑。
- `main` 與本文件是正式設計基線；聊天、研究分支與未合併提案不是正式規格。
- 身分循環與跨生命記憶的詳細規格見 `docs/decisions/GD-002_NAMED_IDENTITY_CYCLE.md`；在原型驗證前不得自行簡化為傳統抽卡／稀有度系統。

## 17. 引擎、製作成本與美術（2026-09-06 使用者確認）

- 客戶端採 Godot，建模、材質與動畫製作採 Blender；世界／模擬核心維持 Rust。
- 美術方向以低資源、高效能、高性價比，同時有良好畫面與辨識度為目標。
- 像素風列入考慮；此決定尚未指定純 2D、2.5D 或即時 3D，也未鎖定鏡頭自由度。
- 畫面判斷須同時考慮人物辨識、戰場閱讀、動作表達、運算資源、資產製作與後續修改成本；不得以「像素」或「低面數」名稱代替驗證。
- 下一個工作階段優先以小型美術樣品確認視覺與製作流程；MP0 的後端驗收範圍維持獨立，不因此加入完整戰鬥或網路系統。
- 降低美術或模擬成本時，仍須維持人物身分、生命歷史與資訊規則，不得為省成本偷偷退回複製武將、全知視角或只按擊殺評價貢獻。
- 技術分工與樣品候選見 [TD-002](decisions/TD-002_GODOT_BLENDER_ART_PIPELINE.md)；先前差異化想法見 [設計想法索引](DESIGN_IDEAS.md)，研究想法保留其待確認狀態。
