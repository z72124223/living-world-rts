# TD-002：Godot、Blender 與美術製作方向

日期：2026-09-06
狀態：工具與成本目標已由使用者確認；具體美術樣式待樣品驗證。
來源：本專案討論中，使用者指定引擎採 Godot、建模採 Blender，要求低資源、高效能、高性價比及良好畫面，並提出像素遊戲可作為參考。

## 已確認

- Godot 4 負責客戶端畫面、鏡頭、輸入、介面、動畫呈現與遊戲打包。
- Blender 負責模型、材質、骨架、動畫，以及需要時的預先渲染素材。
- Rust 的 `crates/world-core` 繼續保存權威世界規則；不因更換客戶端重做第二套人物或武將系統。
- 運算成本與製作成本都納入選型：比較執行效能，也比較製作一個新人物、換裝、增加動作與修正資產的成本。

## 美術樣品候選，尚未定案

| 候選 | 製作方式 | 要實測的取捨 |
|---|---|---|
| 低面數 3D＋像素質感 | Blender 製模與動畫；Godot 使用節制的材質、色盤及適當的畫面解析度 | 近看輪廓、遠看辨識、鏡頭旋轉、骨架與渲染成本；降低解析度不會自動減少世界模擬成本 |
| Blender 預先渲染的像素圖像／2.5D | 從模型與動畫輸出固定方向的圖像，再由 Godot 顯示 | 方向數、動作數及換裝變體造成的素材量，圖像記憶體、遮擋與鏡頭限制 |

工程上先試做可共用的簡單模型與動作，再比較呈現方式；不得把這個試作順序寫成使用者已選定某一美術風格。此輪以這兩種樣品為優先；純手繪 2D 像素仍可在參考風格明確後另行評估，尚未排除。

最新回饋（2026-09-06）優先於上述早期試作順序：使用者否決 v01 的人體與骨架，並指出它與 B 像素圖像差異極大。**本輪以 B 為視覺修正基準**，先修人體／骨架與真正的像素輸出；不能再把低面數 3D 直出當成 B 的交付，也不能由匯入檢查通過宣稱美術合格。最終美術接受度仍由樣品確認。

第一張 [美術方向草案 v01](../../blender-assets/concepts/art-direction-v01.md) 已用內建圖像工具生成並保存提示詞。它只供外觀討論，沒有對應的 3D 模型或動畫，不能替代同一模型的引擎試作與成本驗證。

## 目前的最小樣品與後續比較

2026-09-06 使用者將本輪縮小為「人體＋骨架＋衣服＋胸甲＋武器」。[分件角色 v01](../../blender-assets/samples/modular-character-v01/README.md) 已有可編輯 Blender 模型、共用骨架、姿勢檢查動作、實際渲染及 Godot 匯入證據；尚未完成最終風格比較。使用者同時指出肢體受傷影響與架構衝突，暫停採用、待重新討論，本輪不實作傷害功能。

外觀確認後，再考慮代表性武將、普通士兵、地形及待機／行走動作的比較；這些不再是本輪交付要求。人物近景只是測試尺度，不代表已承諾自由近身操作或任意旋轉鏡頭。

v01 已標為美術不通過，保留原檔。後續 [人體與 B 像素方向 v02](../../blender-assets/samples/body-pixel-v02/README.md) 使用 MakeHuman CC0 人體基底，完成連續人體、重新配置的骨架與固定尺度像素預覽；尚待美術審核，衣甲未重製，亦未沿用 v01 的 Godot 匯入結果。

同一硬體、解析度、鏡頭與動作條件下，記錄畫面、幀時間、CPU／GPU 負載、記憶體／顯示記憶體及資產大小。另記錄製作與修改成本。比較用角色與演出資料須標明為美術展示，不可冒充 Rust 世界模擬完成。

最低硬體、目標幀率、同屏人物數、鏡頭範圍、貼圖尺寸與面數上限仍待樣品結果確認；舊文件數字不沿用為驗收承諾。無畫面的測試不能取代實際渲染與動作檢查。

## 本機工具觀測

2026-09-06 在此開發電腦確認 Godot `4.6.3.stable` 與 Blender `5.1.2` 可呼叫。這是目前試作起點，不是最新版本宣稱，也不是已通過資產匯入或遊戲效能驗收。未來升級須保留可重現的工具版本及匯入結果。
