# 古代軍制／戰場指揮研究 v0.1

> 狀態：研究資料，不是正式遊戲規則。任何內容必須經主設計確認後，才能升格進 `GAME_CONSTITUTION.md` 或 MP 規格。

## 研究目的

為 Living World RTS 的「統一組織樹、指揮鏈、傳令、情報、動態分兵」建立歷史基線。依遊戲鐵律：現實軍制已有成熟解法時，先理解現實，再決定遊戲化程度。

## 目前可確認的方向

### 1. 基層組織應該是層級化，而不是所有士兵直接掛在最高指揮官下

中國古代軍事文獻已可見五、十等基層互保／編組概念。《吳子》〈治兵〉記載「鄉里相比，什伍相保」，顯示小規模分組與責任關係是古代軍隊管理的一部分。

**對遊戲的啟示（尚未升格）：**
- 統一組織樹方向合理。
- 大軍不應讓最高指揮官直接控制每個人物；命令可沿層級下傳。
- 基層單位尺寸不應現在硬鎖為固定 5／10 人；不同時代、軍制、兵種可以不同。

### 2. 旗、鼓、金、鈴等是「低頻寬但快速」的戰場通訊

《尉繚子》〈勒卒令〉明確區分鼓、金、鈴、旗的用途：鼓可代表進／擊，金可代表止／退，旗可指示左右，鈴用於傳令。《通典》亦保存以旗、鼓、角等訓練與指揮部隊的制度描述。

**對遊戲的啟示（尚未升格）：**
- 旗鼓不是用來傳任意長句，而適合預先約定的簡單命令。
- 可將通訊媒介設計成「可傳資訊種類／容量」不同，而不是只有傳輸速度不同。
- 例如「前進／停止／撤退／轉向」可由信號快速傳達；複雜迂迴計畫仍需要更高資訊容量的媒介。

### 3. 長距離或複雜命令需要傳遞鏈；訊號本身也可能需要中繼

《通典》記載行軍縱列過長、鼓聲無法傳達時，可在中段增設鼓以「傳響」，使前後軍能聽到。這證明古代通訊不只是「主將 → 全軍瞬時廣播」，而存在物理距離、可聽範圍與中繼問題。

**對遊戲的啟示（尚未升格）：**
- 通訊可建模為有範圍、延遲、媒介與中繼節點。
- 玩家切斷中繼、殺死傳令人物、阻隔視線／聲音，都可能自然影響指揮，而不是套固定 Debuff。

### 4. 偵察本身是軍隊組織的一部分

《通典》保存紮營／行軍前派可信軍官、嚮導、斥候／騎兵先行察看地形，以及用不同顏色旗幟回報道路、溝渠、河流、林木等資訊的描述。

**對遊戲的啟示（尚未升格）：**
- 偵察不應只是玩家點一下「開視野」。
- 偵察人物／分隊可是真實組織節點，取得情報後還需要把情報傳回。
- 情報具有「觀測時間」，因此回到主隊時可能已經過期。

### 5. 訓練的價值之一，是建立共同的信號語言

古代軍事文獻反覆描述士兵需學會看旗、聽鼓，並依信號完成集結、進退、變陣等動作。這表示通訊效率不只取決於發信端，也取決於受令部隊是否理解並能執行標準化信號。

**對遊戲的啟示（尚未升格）：**
- 未來「訓練／紀律」可以影響命令理解、反應與隊形保持，而不必只做成攻防加成。
- 臨時拼湊的部隊即使人物很強，也可能協同差。

## 初步抽象模型（研究提案）

一條命令未來可考慮包含：

- `issuer`：誰發出
- `issued_at`：何時發出
- `recipient`：目標組織／人物
- `intent`：命令意圖
- `payload_complexity`：資訊複雜度
- `medium`：旗、鼓、傳令人物、書面命令等
- `route`：直接或經中繼
- `received_at`：實際收到時間
- `understood`：是否正確理解
- `freshness`：收到時情報／命令是否仍適用

這不是 MP0 實作需求，只是為後續軍事通訊模組保留概念。

## 暫不下結論的問題

1. 三國／漢末具體到「伍、什、隊、曲、部」等編制在不同時期與軍隊中的實際人數與權責，需要更嚴謹史料交叉驗證。
2. 戰場傳令人物的正式職稱、數量與固定配置不能用後世制度直接倒推漢末。
3. 旗、鼓、金、角的信號表不能假設跨朝代完全一致。
4. 玩家離線與現實軍官失能並不完全等價，永久死亡遊戲仍需額外公平性設計。

## 目前建議回收主幹的候選原則

以下只列候選，尚未正式升格：

- 命令傳遞應受組織層級與通訊媒介約束。
- 戰場信號是低資訊容量的快速通訊；複雜命令需要高容量媒介。
- 通訊可以需要中繼，並受距離／視線／聲音／傳令者存活影響。
- 偵察必須考慮「取得情報」與「把情報送回」兩個不同過程。
- 部隊訓練可以影響共同信號理解與協同行動。
