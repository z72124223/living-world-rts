## 家庭與繼承：保留規則，不在此次建造介面

- 子女出生時設定「公開給其他玩家」或「保留給指定的一位父母帳號」，避免同一子女被兩位父母重複繼承。
- 已由玩家操作的子女不可被其他玩家或父母強制取代。公開子女被接手後，不再是原父母可登入的繼承人。
- 父母死亡後若有自己的合格保留子女，可登入該子女。若沒有，只能重新創角，不把前一個人的資產與聲望複製到陌生的新角色。
- 資產與聲望如何繼承由遊戲內遺產法律決定；可以參考現實或古代制度，具體法律尚未選定。帳號登入權與遺產所有權是兩件事。
- 同性婚姻允許。同性伴侶不產生雙方的生物子女，可領養或接手其他玩家販售的未占用子女。
- 生育採成年男女双方同意的親密互動，可用共同生活、淡出等不露骨方式呈現；妊娠須經過一定週期。時長未定，不製作規避平台審核的內容。
- 收養／轉讓限未被玩家占用的子女，先解除原保留權，再轉移家庭關係；改從新父母角色的姓，不是新父母的真實證件姓氏。
- 出生、監護、交易、保留權、死亡與繼承必須由未來的世界／家庭後端管理。本次的 `children` 表是可接入的最小資料契約，不代表出生系統已完成。

**目前處理：**已寫 Persona 串接程式與原生操作流程；沒有營運方正式帳號、範本及金鑰時顯示「實名驗證服務尚未設定」。不建立虛假的驗證通過資料，不要求把證件或金鑰貼在 AI 對話。申請與部署步驟見 [PERSONA_SETUP.md](PERSONA_SETUP.md)。

使用者同意實名私下綁定帳號，目的包含作弊調查與可能犯罪事件的責任追溯。證件照片只在供應商驗證流程處理。遊戲不公開真名、證號或照片，也不自動把玩家資料交給政府。政府依法調取的流程、保存期限與對應管轄地仍須營運方正式訂定；這份規格不是法律適用性判定。

有效證件＋本人活體比對是此次採用的實名替代方案。**沒有接通政府死亡登記資料庫**，不可宣稱已實際查核政府登記存亡。Persona 是否支援每個營運地區的國民身分證、可可靠提供登記性別與穩定證號，仍須供應商實測確認。

本機版本的 HTTP 只綁 127.0.0.1:8787，拒絕跨站瀏覽器請求與錯誤 Host；不是可以放到公網的正式帳號服務。多人正式版必須移到營運方控制的 HTTPS 後端、集中式資料庫與金鑰管理、備份還原及營運權限環境。玩家控制自己的本機系統，因此這個本機伺服器不能充當線上遊戲的反作弊權威。

尚待外部／後續工作：Persona 申請與正式查核、實際付費 Luna 呼叫、正式隱私條款與申覆窗口、跨證件去重、帳號復原、供應商資料保存與刪除政策、集中式部署、家庭世界資料接入與死亡後角色介面。這些不得寫成已完成。

## 本輪補充：可操作的獨立創角測試

使用者指出未設定項目使流程無法完整試玩，並授權分工補齊後由原窗口驗收。新增「測試創建角色.cmd」與明確 `--registration-demo` 入口，服務僅綁 127.0.0.1:8788；正式入口仍使用 8787。測試全部使用虛構記憶體資料與固定姓名回覆，不接受證件、真實帳密或 API 金鑰，不連接外部服務，也不能把狀態帶入正式帳號。

測試身分固定為女性，僅供走訪畫面，沒有新增玩家性別或外貌選擇權。須依次主動確認模擬實名、模擬 AI，才能用正式核心規則測試首次傳送或同登記性別公開子女。測試子女由伺服器篩選與隨機配對，沿用父母所取的子女既有姓名；重開測試會替換工作階段並清除該輪資料。固定回覆可驗證介面與規則，不能證明真實 AI 審核品質或 Persona 核身成功。

本輪回歸修正：明確重測 AI 連線時先撤銷舊連線與姓名審核，失敗後不能沿用舊授權；保存金鑰不代表連線有效。投胎數量與交易配對共用資格篩選，異常空白姓名或外貌資料不入池，禁止回退為接手玩家自填姓名。

子女目前以受信任世界資料中的 `name_approved` 標記表示出生時的命名已核准，不重新要求接手者取名，也不套用其首次自行取名的 15 分鐘審核紀錄。正式出生審核的来源、政策版本及家庭資料稽核仍待世界後端接入，不能由此布林標記宣稱已完成。现版使用固定成年人物素材且沒有年齡欄位；沒有新增真實玩家年齡查核或完整出生資料驗證。

2026-09-06，依使用者「創建該有的功能你選一項先實裝」，本輪接通子女外貌顯示：`appearance_catalog.gd` 將伺服器保存的 ID 對應到已隨包交付的素材，正式／測試畫面共用；不把資料字串當成任意資源路徑。配對前顯示等待訊息，配對後與再次進入頁面均依角色紀錄顯示，缺失或性別矛盾時顯示素材未備妥，不以別人外貌替代。目前有兩張首次傳送男女圖及一張新增成年聚落女性圖，demo 兩名公開子女共用後者；沒有宣稱每個子女都有獨特肖像、遺傳外貌生成或正式玩家家庭已接入。新素材經 AI 目視檢查，尚待使用者定版。

## 防止再次跑偏

舊 `yiyu-character-creation-v01.png` 被否決，原因是人物寫實與擅加外貌選單。`v02` 是後續程式畫面的視覺基礎；最新指示已從圖片討論進入實作，不再受舊「只討論圖片」範圍限制。實作使用拆開的背景、固定人物素材和原生表單，不把整張有假狀態的概念圖貼成介面。

每次修改先讀 LATTICE 現行決策和此規格，找出涉及的禁止項；交付前查看原生渲染截圖，驗證人物完整、不裁切、外貌唯讀、現代衣服及狀態真實。圖片生成工具只負責素材；靜態圖不能證明動畫可重用或戰鬥效能。這是持久的工作規則與回讀機制，不宣稱已訓練模型權重。
